# 发票邮件发送 · 使用说明

把某个项目里的 **PDF 发票逐张作为附件**，发送到指定邮箱（默认 `13752070316@fapiao56.com` 这类发票归集邮箱）。
全部走系统自带的零依赖 SMTP 客户端，不装任何第三方包。

---

## 一、先配置一次（设置 → 发票邮件发送）

打开系统左侧「设置」，往下找到 **发票邮件发送** 卡片：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 收件人邮箱 | `13752070316@fapiao56.com` | 发票归集邮箱；多个收件人用英文分号 `;` 分隔 |
| 发件人邮箱 | 空 | 你的网易邮箱完整地址，如 `xxxxxx@163.com` |
| 发件人显示名 | 天津仁爱学院报销系统 | 对方收到的「发件人」名称 |
| SMTP 服务器 | `smtp.163.com` | 见下方服务商对照表 |
| SMTP 端口 | `465` | 465 = SSL，25/587 = 明文 |
| SSL 加密 | 勾选 | 465 端口必须勾选 |
| SMTP 账号 | 空 | 网易填完整邮箱地址 |
| SMTP 授权码 | 空 | **不是登录密码**，见下节 |

卡片右上角会实时显示「待完善：× × ×」或「已配置完成」。

### 网易 163 授权码怎么拿

1. 网页登录 <https://mail.163.com> → 顶部「设置」→ **POP3/SMTP/IMAP**
2. 勾选 **开启 SMTP 服务** → 按提示用手机发短信验证
3. 页面给出一串 **16 位左右的授权码**（只显示一次），复制下来
4. 粘到系统设置页的「SMTP 授权码」框里 → 点保存

> 授权码只存在本机数据库 `data/reimburse.db`（该目录不入 Git），接口返回时会自动脱敏成空值，前端永远拿不到明文。
> 想换账号时，点授权码下方「清除已保存的授权码」。

### 常见服务商参数

| 服务商 | SMTP 主机 | 端口 | SSL | 账号 |
| --- | --- | --- | --- | --- |
| 网易 163 | `smtp.163.com` | 465 | ✅ | 完整邮箱地址 |
| 网易 126 | `smtp.126.com` | 465 | ✅ | 完整邮箱地址 |
| QQ 邮箱 | `smtp.qq.com` | 465 | ✅ | 完整邮箱地址 |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465 | ✅ | 完整企业邮箱 |
| Gmail | `smtp.gmail.com` | 465 | ✅ | 完整邮箱 + 应用专用密码 |

## 二、发送发票

**路径**：进入项目 → 第 ③ 步「票据与审核」→ 右上角 **📧 发送发票到邮箱**

- 默认只发送 **已审核通过** 的 PDF 票据（未审核的不发，避免把废票送进归集系统）
- 每张发票是一个独立附件，文件名格式：`序号_项目编号_原文件名.pdf`
- 邮件正文含项目名称、编号、负责人、张数、金额合计，以及逐张的票号 / 销方 / 金额 / 日期清单
- 邮件主题：`[发票] 项目编号 项目名 共 N 张`

发送前会弹确认框告诉你发几张、发到哪个邮箱。

## 三、先用测试邮件验证配置

在设置页点 **发送测试邮件**（不发附件），收到就说明 SMTP 配置没问题，再正式发发票。
常见报错的含义：

| 报错 | 原因 |
| --- | --- |
| `535 Error: authentication failed` | 授权码填错，或填成了邮箱登录密码 |
| `SMTP 指令失败 [553]` | 发件人地址与 SMTP 账号不一致（网易要求相同） |
| `连接 …超时` | 端口被防火墙拦了，换成 465 并勾选 SSL |
| `邮件还没配置好，缺：…` | 设置页还有必填项没填 |
| `附件合计 … MB，超过 25 MB 上限` | 一次发的发票太多，分批或先合并 |

## 三之一、新用户注册登录流程（2026-10-08 定版）

```
新用户打开注册页 → 填本人邮箱 → 点「获取验证码」
      ↓  系统用「系统发件邮箱」给他发 6 位码（5 分钟有效）
填入验证码 + 设置密码 → 提交
      ↓  邮箱校验通过即开通（默认，可关）
用「邮箱 或 登录名」+ 密码登录
```

- 验证码由**系统**发出，用户只需要能收邮件，不需要自己配任何 SMTP。
- 默认**邮箱校验通过即开通**（`auth_register_auto_approve=1`），注册完直接进系统，不用等审批。
- 管理员想改回人工审批：设置页 → **系统发件邮箱（注册验证码）** → 取消勾选
  「邮箱验证码校验通过即开通账号」；之后新注册账号进「待审批」，管理员在 `/admin` 通过后才可登录。
- 邮箱域名白名单（`auth_domain_whitelist`，如 `tjrac.edu.cn`）命中时**无论开关如何都自动通过**。
- 登录支持三种账号名：登录名、邮箱、手机号。

## 三之二、注册验证码用的是另一套「系统发件邮箱」

新用户注册、忘记密码时发的验证码，**不走上面这套个人配置**，而是读全局的「系统发件邮箱」。
两套互相独立，原因：验证码由 `auth.js` 发出，那时还没有用户上下文，只能取全局值（`user_id=0`）。

**没配全局邮箱时，注册页会显示「验证码邮箱尚未配置，暂时无法自助注册」。** 管理员这样解决：

1. 用管理员账号登录 → **设置**页 → 最下方 **系统发件邮箱（注册验证码）**（仅管理员可见）
2. 填发件人邮箱、SMTP 服务器/端口/账号/授权码 → 保存
3. 点 **发送测试邮件** 验证能收到

如果管理员自己已经配好了上面的「发票邮件发送」，点 **复制我上面的配置** 可一键把服务器、端口、
账号抄过来——只有授权码不会回填（接口从不下发明文），手填一次即可。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/mail/global-status` | 全局发件邮箱状态：`ready`、`missing`、`passSet` |
| POST | `/api/mail/global` | 保存全局发件邮箱，**仅管理员** |
| POST | `/api/mail/global-test` | 用全局配置发测试邮件，仅管理员 |

## 四、接口（供二次集成）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/mail/status` | 配置自检：`configured`、`missing` 列表、`passSet`（不返回授权码） |

| POST | `/api/projects/:id/send-invoices` | body `{onlyApproved: true}`（默认 true）→ 返回 `{to, subject, count, total}` |

## 五、自测脚本（不真发信）

```bash
node server/mail_e2e.js
```

会在本机起一个假 SMTP 服务器，把配置临时指向它，发一次真实项目的发票，校验 SMTP 会话与 MIME 结构
（附件数量、PDF 头是否完整、中文文件名 RFC2231、主题 base64 解码），结束后自动恢复原配置。
当前 **16/16 通过**。

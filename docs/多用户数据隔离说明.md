# 多用户数据隔离说明

> 2026-10-08 修复：之前所有登录用户共享同一份数据（谁都能看到、改到别人的项目和邮箱配置）。
> 现在按「项目归属人」隔离，设置分「全校统一」与「仅本人可见」两类。

## 一、隔离规则

| 数据 | 规则 |
|---|---|
| 项目 | 属于创建者（`projects.owner_user_id`）；普通用户只能看/改/删自己的 |
| 行程、成员、票据、归集明细、导出件 | 跟随所属项目 |
| 票据原件 PDF/图片（`/api/files/...`） | 只认自己项目里的票据，猜到文件名也下不了 |
| 仪表盘统计、项目列表、人员搜索 | 只统计/列出自己的 |
| **邮件配置**（收件人/发件人/SMTP/授权码） | **每人一份**，互相看不到，接口也不下发明文 |
| **收款信息**（收款人、开户行、账号） | **每人一份** |
| 差旅补助标准、单位名称、字典（分类/科目/学院/专业） | 全校统一，只有管理员能改 |

管理员（`admin` / `super_admin`）例外：可查看全部项目与票据，用于后台运维与审计。

## 二、实现要点

- **归属校验放在每个接口入口**，不只是在列表接口过滤。只过滤列表的话，对方拿到 id 直接调详情/修改/删除照样能改到别人的数据 —— 这次修的就是这个洞。
- 越权一律返回 `项目不存在或无权访问`，不透露资源是否存在。
- 设置表 `settings` 主键从 `key` 升级为 `(key, user_id)`：`user_id=0` 是全局，大于 0 是个人覆盖。
  身份敏感项（发件邮箱、SMTP 账号、授权码、收款人/开户行/账号）**不继承全局值**，避免把管理员那套账号泄漏给所有人。
- 系统发验证码邮件用的 SMTP 配置仍在全局（`auth.js` 没有用户上下文），与用户的个人发信配置互不干扰。

## 三、存量数据迁移

新字段上线后，历史项目必须补归属人，否则这批数据对所有人同时消失。用：

```bash
node server/migrate_ownership.js --dry     # 先看会做什么
node server/migrate_ownership.js           # 自动挑归属人（优先真实业务账号）
node server/migrate_ownership.js --owner=lhbzx1984   # 指定归属人
```

脚本做两件事（可重复执行，已迁移的会跳过）：

1. `owner_user_id IS NULL` 的项目补上归属人；
2. 把全局的邮件/收款配置复制一份给归属人（全局那份保留，给验证码邮件用）。

本次执行结果：4 个真实项目归 `lhbzx1984`（刘海斌），其 163 邮箱与授权码转为个人配置。

## 四、回归测试

```bash
npm run test:isolation    # 多用户隔离专项：33 项
npm test                  # API 冒烟 81 项
npm run test:ui           # UI 冒烟
npm run test:mail         # 发信端到端 16 项
```

`server/isolation_test.js` 自建两个临时账号，覆盖：列表/详情/修改/删除越权、成员与行程越权写入、
票据原件下载 403、邮件与收款设置互不可见、非管理员改不动全校标准、仪表盘口径、人员搜索范围；
跑完账号与项目全部删除，库里不留痕迹。

## 五、已知边界

- 未开启「必须登录」（`auth_require_login=0`）时仍是单机共享模式，不做隔离 —— 那种模式本来就假定只有一个人用。
- 项目分类 / 费用科目 / 学院 / 专业字典仍允许所有登录用户增删（属业务便利项，非敏感数据）。
- 项目归属暂不支持在界面上转移；如需调整，用 `node server/migrate_ownership.js --owner=<账号>` 或直接改库。
